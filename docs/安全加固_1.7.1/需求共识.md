## 需求理解（产品语言）

1. **今天必须堵住的洞**：线上数据库有四张存用户数据的表，任何访客拿网页里公开的匿名钥匙就能读、改、删（用户画像、加密后的 API Key、聊天记录含 IP、AI 知识库）。要立刻关门，并清理已经下线的"匿名试用"残留。
2. **1.7.1 安全加固**：不设防的接口加上门禁（全量重抓、覆盖共享点评、登录/注册/后台登录限流、聊天限流不可绕过、会话归属校验）；抓数据的请求加超时；程序被重启时要体面收尾；出错不把内部信息暴露给用户；加一个"健康检查"让运维能探活。
3. **工程补全**：数据库结构进仓库（能从零重建）、补 `npm test`、补版本 tag、修一堆和代码对不上的文档。
4. **前端修补**：搜索卡顿、请求无超时、流式回答断线丢内容、隐私模式登录崩、若干小 bug 与死代码。

## 我替用户拍板的决定（供事后一眼纠错）

| 决定 | 理由 |
|---|---|
| 全量刷新授权采用「token 或后台登录或本机直连」三选一，而不是强制 token | 服务器 `.env` 还没加 token 之前，每日 cron 仍能工作，不会因为发版顺序出现"刷新中断一天" |
| 冷却期内的刷新请求返回现有数据（200 + `refreshSkipped`），而不是 429 | cron 脚本收到 429 会记为失败，其实数据是新的，没必要报错 |
| 抓取失败改为抛错（不再返回空值） | 空值 + 已抓取时间戳会把失败永久固化，这是数据层最实际的 bug |
| `unhandledRejection` 只记录不退出；`uncaughtException` 记录后退出交给 PM2 | 前者多是已 catch 的 fire-and-forget 任务的漏网之鱼，杀进程代价大于收益；后者进程状态不可信 |
| `POST /api/fund/:code/ai-summary` 改为仅限后台管理员 | 它用平台 Key 花钱并覆盖全站共享内容，前端没有任何地方调用它 |
| 删除 `data.js` 的原型假数据与 `CountUp` / `Sparkline` 死组件 | 零引用；假数据带假日期假经理名，容易误导后来者 |
| 基金卡片加键盘可达（Tab + Enter/空格） | 成本极低，700 张卡片全部键盘不可达是明显的可访问性缺陷 |
| 版本号定为 1.7.1（修订号） | 无用户可见新功能，"现在你可以……了"说不出来，按规矩走修订号 |
| 不做列表虚拟化/分页 | 这是 UX 改动，需用户确认；先用 memo 解决输入卡顿 |
